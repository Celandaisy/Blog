先说结论：我这套东西不是"做个 3D 动画"，也不是"让 2D 假装有 3D"。

**就是同一个机位，两边各画各的，最后拼起来。**

角色在 Toon Boom Harmony 里画，环境在 Blender 里渲，中间靠几个 JSON 传话，最后在 After Effects 里合上。

听起来简单，做起来全是坑。这篇就把整条链路讲一遍，给以后的自己看，也给同样在折腾的人参考。

![整条链路](/assets/pipeline/flow.png)

---

## 一、先把分工定死

这一步想不清楚，后面全是白工。

**动画这行有个老道理：相机是表演工具，不是渲染参数。**

调机位的时候眼睛得盯着角色——角色在哪、构图舒不舒服、这一推有没有把表情推没了。如果机位在 Blender 调、角色在 Harmony 画，那就是隔着两个软件做构图，来回切，效率极低。

所以我这边的分工是：

- **Harmony = 导演台**：角色、表演、机位，全在这儿定
- **Blender = 摄影棚**：只按给定机位，把 3D 环境拍出来
- **AE = 剪辑台**：把上面两边的素材叠起来，加效果

数据只能**单向**流：Harmony → Blender。

代价也得认：Blender 是下游，机位一改，3D 就得重渲。所以真做起来还得配一条"低清预览"的快车道，不然每次调个机位都要等半天渲染。

---

## 二、一共 7 张图 + 3 个 JSON

别被这个数字吓到，其实就分两类。

![7 个 Pass 分两类](/assets/pipeline/matrix.png)

**"组图"的意思**：直接叠上去组成画面，少了画面缺一块。

**"改进"的意思**：不叠，当参数用。少了画面还在，只是没效果（比如没景深、没受光）。

具体是这些：

| 谁出的 | 名字 | 干什么用 |
|---|---|---|
| Harmony | `char_color` | 角色色块 |
| Harmony | `char_line` | 描边 |
| Harmony | `char_eyes` | 眼睛（后面做发光） |
| Harmony | `char_normal` | **法线**，给 AE 重打光用 |
| Blender | `env_beauty` | 环境本体，**角色影子已经烤在里面** |
| Blender | `env_depth` | 深度，做雾和景深 |
| Blender | `env_matte` | 遮挡，决定谁盖住谁 |
| Blender | `light.json` | 所有灯的方向/位置/颜色/强度 |

另外两个 JSON（`camera.json`、`character.json`）**不进 AE**，它们只服务 Blender。

### 有个坑必须记住

**数据通道绝对不能当图片处理。**

法线、深度、遮挡这些是"数据"，不是"颜色"：

- 不能过色彩管理（一过 gamma 就废）
- 不能有损压缩（必须 ZIP 无损）
- 不能上滤镜（Kuwahara 一跑全糊）

道理很简单：数据里每个数值都是有意义的，你要是按图片的规则去"美化"它，信息就毁了。

## 三、顺序不能乱

![顺序](/assets/pipeline/flow.png)

```
① Harmony 渲角色（4 个 pass）
② Blender 导入 camera.json + character.json，指定角色图当影子平面
③ Blender 导出 light.json
④ Blender 渲环境（3 个 pass，带影子）
⑤ AE 合成
```

为什么是这个顺序？

- **角色必须先渲**：影子平面得贴角色的图，才知道影子长什么样
- **光必须最后导**：要读角色代理在场景里的位置

顺序反了，影子就是空的，光就是错的。

---

## 四、AE 里怎么叠

从下往上，八层：

![AE 层序](/assets/pipeline/layers.png)

```
⑧ 调色 / 颗粒 / 暗角
⑦ 大气（雾、景深）
⑥ 前景遮挡
⑤ 眼睛发光（Add + Glow）
④ 描边
③ 角色（法线重打光）
② 角色影子（已烤在环境里）
① 环境
```

注意第 ② 层：**影子不在 AE 里做**。渲环境的时候就烤进去了，AE 只是接着用。省一层算一层。

第 ③ 层是重头戏：角色的法线图进 AE，用 Normality 重新打一遍光。好处是**光的方向随时能改**，不用回 Harmony 重渲。

## 五、踩过的坑（重点）

### 相机对不上，差了 4.5

Harmony 的机位导到 Blender，怎么弄都差半格。

折腾了很久才搞明白：两边用的不是同一套坐标约定。Harmony 的 OGL 是屏幕空间、原点在画面中心；Blender 的相机是世界空间 + 视锥参数。中间那个常数 **4.5** 是反解出来的。

现在五类工况（相机运动、模型位移、缩放、旋转、动态 FOV）测下来，**误差 0–1 像素**。对到这个程度之后，这一步就能脚本化了。

### 代理老是对不上

一开始按"角色在画面里的位置"去对 proxy，怎么都对不上。

**错在：要对的是平面中心，不是角色位置。**

角色站在画面左下角，不代表那个平面在左下角。得读平面（plane/peg）的变换，再套到 proxy 上。

### 法线图的两个坑

1. **8 位会有台阶**：法线是数据，256 级不够，必须 16/32 位
2. **G 轴方向反的**：和 Normality 的约定相反，光一打凹凸全反，像浮雕被压进去

检查办法很土：渲一个球的法线，光从左上来，左上应该是亮的。不亮就翻转。

- ✅ 角色 4 个 pass 能出

- ✅ AE 能合，法线重打光能用

## 最后，为什么非要这么折腾

因为 2D 的情绪表达和 3D 的空间感，是两种东西，各有各的好。

全都用 2D 做，镜头一动就露馅；全都用 3D 做，角色那点手绘的味道又没了。

**混着来，才能两边都要。**

虽然代价是——你得同时维护三套软件、十几个 pass、外加一堆自己写的脚本。

但每次镜头一推，角色和背景严丝合缝地对上那一瞬间，还是挺爽的。
